# PMP Commonly Confused Services and Concepts

Side-by-side comparisons of the PMP services and ideas that exam questions most often set against each other. Each table ends with the one thing to remember.

- [Domain 1: People](#domain-1-people)
- [Domain 2: Process](#domain-2-process)
- [Domain 3: Business Environment](#domain-3-business-environment)

## Domain 1: People

### Project Vision vs Project Scope

|          | Project vision                                               | Project scope                                          |
| -------- | ------------------------------------------------------------ | ------------------------------------------------------ |
| Answers  | Why the project exists and what outcome it must create       | What will be delivered                                 |
| Where    | Charter, product vision statement, product box, roadmap      | Scope baseline (predictive) or product backlog (agile) |
| Owner    | Sponsor (chartered objectives), product owner (product goal) | Change control (predictive), product owner (agile)     |
| Used for | Judging trade-offs and changes against the outcome           | Defining and verifying deliverables                    |

**Remember:** a fixed, approved scope does not make the vision redundant. The vision is the test every trade-off is measured against.

### Collaborate vs Compromise

|          | Collaborate / problem solve                      | Compromise / reconcile                     |
| -------- | ------------------------------------------------ | ------------------------------------------ |
| Works on | Underlying needs and interests                   | Stated positions                           |
| Result   | Win-win both parties commit to                   | Each side gives something up               |
| Needs    | Time, openness, a neutral facilitator            | Roughly equal power and a quick decision   |
| Exam cue | "time before the decision", "lasting commitment" | "equal authority", "decision needed today" |

**Remember:** splitting the difference is compromise. If the same dispute keeps coming back and there is time, move to collaboration on the underlying needs.

### Smooth vs Withdraw

|           | Smooth / accommodate                            | Withdraw / avoid                               |
| --------- | ----------------------------------------------- | ---------------------------------------------- |
| What      | Stress common ground; one side concedes         | Retreat from or postpone the issue             |
| Fits      | Low-stakes issue where the relationship matters | Tempers need to cool and the decision can wait |
| Substance | Left unresolved                                 | Left unresolved                                |

**Remember:** neither resolves the issue. Use them for trivial matters or a temporary cool-down, then come back if it matters.

### Servant Leadership vs Situational Leadership

|                  | Servant leadership                                 | Situational leadership                                         |
| ---------------- | -------------------------------------------------- | -------------------------------------------------------------- |
| Core idea        | Put the team's needs first; enable, do not command | Match direction and support to each person's development level |
| Actions          | Remove obstacles, coach, shield the team           | Directing, coaching, supporting, delegating                    |
| Role on the exam | PMI's default stance                               | How to adapt within that stance                                |

**Remember:** they work together. Serve the team, and choose how much direction and support each person needs on this specific task.

### Self-Awareness vs Self-Management vs Social Awareness vs Relationship Management

|                         | Focus                 | Example                                    |
| ----------------------- | --------------------- | ------------------------------------------ |
| Self-awareness          | Recognize own emotion | Noticing a deadline is making you curt     |
| Self-management         | Control own emotion   | Regaining composure before giving bad news |
| Social awareness        | Read others           | Sensing a stakeholder's unease from tone   |
| Relationship management | Act on that reading   | Following up in a way that builds trust    |

**Remember:** awareness recognizes, management acts. "Self" is about you; "social" and "relationship" are about others.

### Power/Interest Grid vs Salience Model

|            | Power/interest grid                                    | Salience model                             |
| ---------- | ------------------------------------------------------ | ------------------------------------------ |
| Dimensions | Power and interest                                     | Power, legitimacy, urgency                 |
| Output     | Manage closely, keep satisfied, keep informed, monitor | Dormant through definitive (seven classes) |
| Best for   | Choosing an engagement strategy                        | Deciding whose claims need attention now   |

**Remember:** if the question mentions legitimacy or urgency, it is the salience model. Legitimacy plus urgency without power is "dependent".

### Keep Satisfied vs Keep Informed

|         | Keep satisfied                             | Keep informed                                  |
| ------- | ------------------------------------------ | ---------------------------------------------- |
| Who     | High power, low interest                   | Low power, high interest                       |
| Contact | Concise updates at their decision points   | Regular updates, demos, a feedback channel     |
| Example | A busy executive controlling a budget line | Staff whose daily work the project will change |

**Remember:** the powerful but disengaged get short, decision-focused contact. More detail does not create engagement.

### Majority vs Plurality vs Unanimity

|           | Rule                   | Watch out for                    |
| --------- | ---------------------- | -------------------------------- |
| Unanimity | Everyone agrees        | Can stall indefinitely           |
| Majority  | More than 50% of votes | Most votes under 50% has not won |
| Plurality | Largest block wins     | Can win with well under half     |

**Remember:** when the agreed rule is majority and the leading option is under half, run a run-off between the leaders.

### Mentoring vs Training vs Coaching

|         | Training                          | Mentoring                                          | Coaching                              |
| ------- | --------------------------------- | -------------------------------------------------- | ------------------------------------- |
| Closes  | A specific knowledge or skill gap | Judgement and confidence in a role                 | Performance on goals the person sets  |
| Form    | Course or event                   | Ongoing relationship with someone who did the role | Structured questioning conversations  |
| Trigger | New tool or standard, no baseline | Knows the theory but keeps reverting               | Wants to improve a specific behaviour |

**Remember:** trained but still drifting back to old habits points to mentoring.

### Control Quality vs Validate Scope

|          | Control quality            | Validate scope                     |
| -------- | -------------------------- | ---------------------------------- |
| Question | Did we build it correctly? | Does the customer accept it?       |
| Who      | Team and quality staff     | Customer or sponsor                |
| Output   | Verified deliverables      | Accepted deliverables (documented) |

**Remember:** verify first, then validate. Informal approval is not acceptance.

### Gold Plating vs Scope Creep vs Approved Change

|                 | Driven by                               | Controlled?                                  |
| --------------- | --------------------------------------- | -------------------------------------------- |
| Gold plating    | The team adding unrequested work        | No                                           |
| Scope creep     | Stakeholders adding requests informally | No                                           |
| Approved change | Anyone may propose it                   | Yes, via change control or the product owner |

**Remember:** a good idea from the team is offered to the customer through change control, not built quietly.

### Tacit vs Explicit Knowledge

|          | Explicit                                  | Tacit                                  |
| -------- | ----------------------------------------- | -------------------------------------- |
| Form     | Documents, code, procedures               | Experience, judgement, relationships   |
| Transfer | Repositories, wikis, training material    | Shadowing, pairing, coaching, practice |
| Exam cue | "already documented", "in the repository" | "just knows", "can't explain how"      |

**Remember:** a manual or course cannot carry a skill the expert cannot put into words.

### Push vs Pull vs Interactive Communication

|          | Push                                | Pull                                | Interactive                        |
| -------- | ----------------------------------- | ----------------------------------- | ---------------------------------- |
| How      | Sent to named recipients            | Placed where people fetch it        | Real-time exchange                 |
| Best for | Targeted summaries                  | Large audiences, reference material | Urgent, complex, sensitive matters |
| Weakness | Confirms sending, not understanding | People must choose to look          | Needs people available together    |

**Remember:** need both understanding and a record? Hold a meeting, then send the minutes.

### Acknowledgement vs Understanding

|            | Acknowledgement                | Understanding                                 |
| ---------- | ------------------------------ | --------------------------------------------- |
| Shows      | The message arrived            | The receiver knows what it means and will act |
| Check with | A reply, a read receipt, "yes" | Summarize back, an explicit commitment to act |

**Remember:** "understood" can mean "I heard you". Ask for a paraphrase.

## Domain 2: Process

### Magnitude vs Complexity

|                   | Magnitude                                       | Complexity                                                                        |
| ----------------- | ----------------------------------------------- | --------------------------------------------------------------------------------- |
| Describes         | How much work there is                          | How hard the outcome is to predict                                                |
| Signals           | Budget, sites, teams, duration, identical units | Unclear requirements, new technology, interdependencies, conflicting stakeholders |
| Planning response | More decomposition, coordination, control       | Shorter feedback loops, experiments, frequent re-planning                         |

**Remember:** a huge routine project can be predictive; a tiny uncertain one may need adaptive elements. Uncertainty drives the approach, not size.

### Iterative vs Incremental

|              | Iterative                                              | Incremental                                     |
| ------------ | ------------------------------------------------------ | ----------------------------------------------- |
| Requirements | Refined through rounds of feedback                     | Known and stable enough for each piece          |
| Delivery     | Once                                                   | Frequent, usable pieces                         |
| Example      | A course redesigned through pilots, then launched once | A reporting suite released one report at a time |

**Remember:** agile is both iterative and incremental. Each of the others has only one of those properties.

### Project Management Plan Components vs Project Documents

|          | Plan components                                                         | Project documents                                                      |
| -------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Examples | Subsidiary plans, scope/schedule/cost baselines, change management plan | Project schedule, cost estimates, risk register, issue log, change log |
| Changes  | Only through change control                                             | Updated as work proceeds                                               |

**Remember:** the schedule baseline is a component; the project schedule is a document. The change management plan is a component; the change log is a document.

### Analogous vs Parametric vs Bottom-Up Estimating

|          | Analogous                      | Parametric                        | Bottom-up                        |
| -------- | ------------------------------ | --------------------------------- | -------------------------------- |
| Basis    | A similar past project's total | Unit rate × quantity              | Each work package, rolled up     |
| When     | Early, little detail           | Repetitive work, reliable history | WBS decomposed, accuracy matters |
| Accuracy | Lowest                         | Good if the rate is reliable      | Highest, most effort             |

**Remember:** analogous scales a whole; parametric multiplies a per-unit rate.

### Beta (PERT) vs Triangular Estimate

|                | Beta (PERT)                   | Triangular      |
| -------------- | ----------------------------- | --------------- |
| Formula        | (O + 4M + P) ÷ 6              | (O + M + P) ÷ 3 |
| Weights        | Most likely counts four times | All three equal |
| O 6, M 9, P 18 | 10                            | 11              |

**Remember:** read which distribution the question names before calculating.

### Exclusion vs Assumption

|          | Exclusion                                                         | Assumption                                  |
| -------- | ----------------------------------------------------------------- | ------------------------------------------- |
| Status   | Confirmed as outside scope                                        | Uncertain but treated as true for planning  |
| Recorded | Project scope statement                                           | Assumption log (and possibly risk register) |
| Example  | The landlord confirmed it does the fit-out under its own contract | The landlord is expected to finish by June  |

**Remember:** logging a confirmed fact as an assumption makes it look negotiable.

### Acceptance Criteria vs Definition of Done vs Definition of Ready

|            | Acceptance criteria          | Definition of done                        | Definition of ready                    |
| ---------- | ---------------------------- | ----------------------------------------- | -------------------------------------- |
| Applies to | One item                     | Every item                                | Items about to enter an iteration      |
| Question   | Does it do what was asked?   | Does it meet the shared quality standard? | Is it clear and sized enough to start? |
| Owner      | Product owner, with the team | The team, within organizational standards | Team and product owner                 |

**Remember:** ready is an entry condition; done is an exit condition. A need that applies to every item belongs in done.

### WBS vs WBS Dictionary vs Scope Statement

|         | Scope statement                                              | WBS                                             | WBS dictionary                                               |
| ------- | ------------------------------------------------------------ | ----------------------------------------------- | ------------------------------------------------------------ |
| Holds   | Product scope, deliverables, acceptance criteria, exclusions | Hierarchy of deliverables down to work packages | Detail of each component (owner, cost, criteria, milestones) |
| Answers | Where is the boundary?                                       | What pieces make up the work?                   | What exactly is in this piece?                               |

**Remember:** the three together, approved, are the scope baseline.

### Work Package vs Planning Package vs Activity

|        | Planning package                             | Work package                       | Activity                               |
| ------ | -------------------------------------------- | ---------------------------------- | -------------------------------------- |
| Where  | Under a control account                      | Lowest WBS level                   | The schedule                           |
| Detail | Known but not yet decomposed; carries budget | Estimable, assignable, monitorable | An action that produces a work package |

**Remember:** WBS elements are nouns (deliverables); activities are verbs.

### MMF vs MVP

|          | Minimum marketable feature                            | Minimum viable product                       |
| -------- | ----------------------------------------------------- | -------------------------------------------- |
| Purpose  | Earn value: smallest standalone piece customers value | Learn: smallest version to test a hypothesis |
| Use when | Value is understood; sequence by value                | Value itself is uncertain                    |

**Remember:** MMF starts the return on investment; MVP buys evidence.

### NPV vs Payback Period

|         | NPV                                            | Payback period                           |
| ------- | ---------------------------------------------- | ---------------------------------------- |
| Tells   | Value created in today's money                 | How fast the investment is recovered     |
| Ignores | Nothing material if the discount rate is sound | Cash after payback, time value of money  |
| Role    | Chooses between mutually exclusive options     | A screen, when the organization sets one |

**Remember:** screen by payback only if a limit is stated, then rank the survivors by NPV.

### Output vs Outcome, Leading vs Lagging

|          | Output                       | Outcome (lagging)                  | Leading indicator                      |
| -------- | ---------------------------- | ---------------------------------- | -------------------------------------- |
| Shows    | Work produced                | Whether the benefit arrived        | Early signal that predicts the outcome |
| Examples | Velocity, features, CPI, SPI | Claim settlement time, energy cost | First-month use of a new workflow      |

**Remember:** strong outputs with a flat outcome means diagnose with stakeholders, not ship more features.

### Resource Smoothing vs Resource Leveling

|               | Smoothing                            | Leveling                                 |
| ------------- | ------------------------------------ | ---------------------------------------- |
| Uses          | Float only                           | Any date movement needed                 |
| Finish date   | Never moves                          | May extend                               |
| Critical path | Unchanged                            | May change                               |
| Fits          | Fixed end date, overloads have float | Date can move, no float, no extra people |

**Remember:** smoothing can leave some overallocation; leveling removes it by spending time.

### RBS vs WBS vs OBS

|             | WBS                   | RBS                            | OBS                         |
| ----------- | --------------------- | ------------------------------ | --------------------------- |
| Breaks down | Deliverables and work | Resources by category and type | Organizational units        |
| Answers     | What work?            | What kinds of resource?        | Which unit owns which work? |

**Remember:** to see spend on labour versus equipment, you need the RBS.

### Fixed Price vs Cost-Reimbursable vs Time and Materials

|           | Fixed price              | Cost-reimbursable | Time and materials                   |
| --------- | ------------------------ | ----------------- | ------------------------------------ |
| Scope     | Fully defined and stable | Uncertain         | Small, undefined, or buying capacity |
| Cost risk | Seller                   | Buyer             | Buyer (cap with not-to-exceed)       |
| Ceiling   | FPIF has a ceiling price | None              | NTE limit if agreed                  |

**Remember:** the less precisely the deliverable can be described, the further you move from fixed price.

### RFI vs RFQ vs RFP

|                | RFI                         | RFQ                           | RFP                                 |
| -------------- | --------------------------- | ----------------------------- | ----------------------------------- |
| Buyer knows    | Little; learning the market | Exactly what it wants         | The problem, not the solution       |
| Sellers return | Information, no offer       | A price for the specification | A proposed approach, team and price |

**Remember:** standard, fully specified item compared on price → RFQ.

### Contingency Reserve vs Management Reserve

|               | Contingency reserve                    | Management reserve                            |
| ------------- | -------------------------------------- | --------------------------------------------- |
| For           | Identified risks (known-unknowns)      | Unidentified in-scope work (unknown-unknowns) |
| Location      | Inside the cost baseline (part of BAC) | Outside the baseline, inside the budget       |
| Who uses it   | Project manager, per the plan          | Management, released via change control       |
| Effect on BAC | None when drawn                        | BAC rises when released                       |

**Remember:** neither reserve covers poor performance; that is a variance for governance.

### Actual Cost vs Commitments

|              | Actual cost                                 | Commitments                            |
| ------------ | ------------------------------------------- | -------------------------------------- |
| What         | Cost of work performed (including accruals) | Signed orders for work not yet started |
| Used in EVM? | Yes                                         | No; tracked against funding            |

**Remember:** record cost when the work is done, not when the invoice is paid.

### Typical vs Atypical EAC

|                         | Typical (cause continues) | Atypical (one-off) |
| ----------------------- | ------------------------- | ------------------ |
| Formula                 | BAC ÷ CPI                 | AC + (BAC − EV)    |
| BAC 600, EV 240, AC 300 | 750                       | 660                |

**Remember:** if the original estimates were flawed, neither applies: use AC + a new bottom-up ETC.

### Manage Quality vs Control Quality

|                    | Manage quality                               | Control quality                     |
| ------------------ | -------------------------------------------- | ----------------------------------- |
| Examines           | The process                                  | The output                          |
| Tools              | Audits, process analysis, design for quality | Inspection, testing, control charts |
| Prevents or finds? | Prevents                                     | Finds                               |

**Remember:** a recurring defect is a process problem; more inspection will not stop it.

### Control Limits vs Specification Limits

|           | Control limits                     | Specification limits         |
| --------- | ---------------------------------- | ---------------------------- |
| Come from | The process's own data (about ±3σ) | The customer's requirements  |
| Judge     | Whether the process is stable      | Whether a unit is acceptable |

**Remember:** a point outside the control limits needs investigation even if the unit is in spec.

### Prevention vs Appraisal vs Internal Failure vs External Failure

|                  | Type           | Asks                                     |
| ---------------- | -------------- | ---------------------------------------- |
| Prevention       | Conformance    | Does it stop a defect being made?        |
| Appraisal        | Conformance    | Does it look for defects?                |
| Internal failure | Nonconformance | Defect found before the customer had it? |
| External failure | Nonconformance | Defect found by the customer?            |

**Remember:** maintaining test equipment is appraisal; training is prevention; a warranty repair is external failure.

### Total Float vs Free Float

|          | Total float         | Free float                      |
| -------- | ------------------- | ------------------------------- |
| Protects | Project finish date | The next activity's early start |
| Size     | Always ≥ free float | Always ≤ total float            |

**Remember:** a delay within free float affects nothing; beyond total float it moves the finish.

### Crashing vs Fast Tracking

|          | Crashing                            | Fast tracking                                   |
| -------- | ----------------------------------- | ----------------------------------------------- |
| Adds     | Cost                                | Risk                                            |
| Needs    | Resource-driven critical activities | Discretionary dependencies on the critical path |
| Fails on | Fixed durations (curing)            | Mandatory dependencies                          |

**Remember:** both only help on the critical path; recheck for a new critical path after each step.

### Lead vs Lag

|        | Lead                               | Lag                                     |
| ------ | ---------------------------------- | --------------------------------------- |
| Effect | Successor starts earlier (overlap) | Successor waits                         |
| Work?  | Real parallel work                 | Elapsed time only; no resources or cost |

**Remember:** a wait that needs effort, such as a review, is an activity, not a lag.

### Burndown vs Burnup

|              | Burndown                           | Burnup                                     |
| ------------ | ---------------------------------- | ------------------------------------------ |
| Plots        | Work remaining                     | Completed work and total scope, separately |
| Scope change | Hidden (nets off against progress) | Visible as the scope line moving           |

**Remember:** parallel burnup lines mean scope grows as fast as delivery; no finish can be forecast.

### Lead Time vs Cycle Time

|        | Lead time                | Cycle time              |
| ------ | ------------------------ | ----------------------- |
| Starts | When the request is made | When work starts        |
| View   | The customer's wait      | The team's working time |

**Remember:** Little's Law: cycle time = WIP ÷ throughput, so lowering WIP shortens cycle time.

### Deliverable Acceptance vs Completion Approval

|          | Deliverable acceptance              | Completion approval                               |
| -------- | ----------------------------------- | ------------------------------------------------- |
| Confirms | One output meets its criteria       | The project or phase met its closure criteria     |
| When     | Throughout delivery                 | End of phase or project                           |
| Who      | Customer, or product owner in agile | The authority named in governance or the contract |

**Remember:** all deliverables accepted still leaves formal completion approval and the closing activities.

### Iteration Retrospective vs Final Retrospective

|         | Iteration retrospective             | Final project retrospective                       |
| ------- | ----------------------------------- | ------------------------------------------------- |
| Scope   | The last iteration                  | The whole project, including handover and vendors |
| Purpose | Improvements for the next iteration | Lessons for future teams and the organization     |
| Output  | Team's next iteration               | Lessons learned repository, process owners        |

**Remember:** there is no next iteration at closure, so the audience is the organization.

## Domain 3: Business Environment

### Project Governance vs Project Management

|               | Project governance                                                                            | Project management                                                  |
| ------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| Core question | Who has authority to decide, and how is the project overseen?                                 | How will the team plan and deliver the work?                        |
| Content       | Decision rights, approval levels, oversight bodies, escalation paths and thresholds, policies | Scope, schedule, cost, quality and other plans; baselines; backlogs |
| Owners        | Sponsor, steering committee, PMO, gate boards                                                 | Project manager and team                                            |

**Remember:** a change management plan describes how a change is processed; governance decides who may approve it.

### OPAs vs EEFs

|                     | Organizational process assets                                              | Enterprise environmental factors                                         |
| ------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| What                | The organization's own processes, templates, policies, knowledge           | Conditions the project works within                                      |
| Examples            | Approval procedure, risk template, lessons repository, own historical data | Culture, risk appetite, laws, market conditions, purchased industry data |
| Project can update? | Yes, through the asset's owner                                             | No; it responds to them                                                  |

**Remember:** classify by what it is, not where it sits. Culture is internal but is still an EEF.

### Supportive vs Controlling vs Directive PMO

|                           | Supportive    | Controlling                | Directive                  |
| ------------------------- | ------------- | -------------------------- | -------------------------- |
| Control                   | Low           | Moderate                   | High                       |
| Requires its standards?   | No (optional) | Yes, and audits compliance | Yes                        |
| Manages projects and PMs? | No            | No                         | Yes; PMs report to the PMO |

**Remember:** two questions identify the type: does it require and check compliance, and does it manage the project managers?

### Identified Risk Occurs vs Unidentified Problem Occurs

|             | Identified risk occurs                           | Unidentified problem occurs                                |
| ----------- | ------------------------------------------------ | ---------------------------------------------------------- |
| Response    | Risk owner runs the planned contingency response | Workaround agreed with those affected                      |
| Funded from | Contingency reserve, inside the cost baseline    | Management reserve, outside the baseline                   |
| Released by | PM or risk owner, per the risk management plan   | Sponsor or management; baseline updated via change control |
| Records     | Issue logged; register entry marked as occurred  | Issue logged with an owner and target date                 |

**Remember:** an identified risk that occurs draws contingency; a surprise needs a workaround and approved management reserve.

### Change Control vs Configuration Management

|                    | Change control                                                    | Configuration management                                  |
| ------------------ | ----------------------------------------------------------------- | --------------------------------------------------------- |
| Decides            | Whether a change happens                                          | That the result is recorded, versioned and used           |
| Activities         | Document, analyze, decide, communicate, implement, verify, update | Identification, status accounting, verification and audit |
| Failure looks like | Acting on an unapproved request                                   | Teams working from different versions; lost edits         |

**Remember:** approving a change does not stop people using an old version; configuration management does.

### Corrective Action vs Preventive Action vs Defect Repair vs Update

|                   | Fixes                                                    |
| ----------------- | -------------------------------------------------------- |
| Corrective action | Current performance that is off plan                     |
| Preventive action | Future performance, so a problem does not occur or recur |
| Defect repair     | A nonconforming product                                  |
| Update            | Controlled documents or plans                            |

**Remember:** fixing the product is defect repair; fixing how the project is performing now is corrective.

### Emergency Change vs Unauthorized Change

|           | Emergency change                                      | Unauthorized change                                  |
| --------- | ----------------------------------------------------- | ---------------------------------------------------- |
| Approval  | On the spot by the person the plan names              | None; discovered after the fact                      |
| Condition | Meets the plan's emergency criteria                   | Made outside the process                             |
| Next step | Document and review afterwards within the plan's time | Document, assess, and let the right authority decide |

**Remember:** the plan's definition decides what counts as an emergency, not the requester's label.

### Risk vs Issue

|                   | Risk                                          | Issue                                    |
| ----------------- | --------------------------------------------- | ---------------------------------------- |
| Status            | Uncertain; may or may not happen              | Has happened or is certain               |
| Recorded          | Risk register (probability, impact, response) | Issue log (owner, target date, status)   |
| Becomes the other | When the event occurs or is certain           | A certain fact can still cause new risks |

**Remember:** a trigger or a higher probability does not turn a risk into an issue.

### Contingency Plan vs Fallback Plan vs Workaround

|                  | Planned? | Used when                                         |
| ---------------- | -------- | ------------------------------------------------- |
| Contingency plan | Yes      | The trigger fires for an identified risk          |
| Fallback plan    | Yes      | The contingency plan proves ineffective           |
| Workaround       | No       | An unidentified or passively accepted risk occurs |

**Remember:** switching to a fallback is executing the plan; a workaround is improvising for something nobody planned.

### Exploit vs Enhance vs Share

|         | Effect on the opportunity                          |
| ------- | -------------------------------------------------- |
| Exploit | Makes it certain                                   |
| Enhance | Raises probability or impact; still uncertain      |
| Share   | Gives part of the benefit to a better-placed party |

**Remember:** "secure the opportunity" points to exploit.

### Transfer vs Mitigate

|                     | Transfer                                        | Mitigate                                  |
| ------------------- | ----------------------------------------------- | ----------------------------------------- |
| Changes             | Who bears the consequence                       | Probability or impact                     |
| Threat still there? | Yes                                             | Reduced                                   |
| Examples            | Insurance, warranty, fixed-price contract, bond | Fixing a configuration, changing a design |

**Remember:** an insured shipment can still be lost; keep monitoring a transferred risk.

### Residual Risk vs Secondary Risk

|          | Residual risk                 | Secondary risk                              |
| -------- | ----------------------------- | ------------------------------------------- |
| Is       | What remains after a response | A new risk created by the response          |
| Handling | Record; usually accepted      | Identify, analyze and respond like any risk |

**Remember:** a second supplier reduces delivery risk (residual) but may add quality inconsistency (secondary).

### Risk Review vs Risk Audit

|      | Risk review                                | Risk audit                                             |
| ---- | ------------------------------------------ | ------------------------------------------------------ |
| Asks | Are the risks in the register still right? | Is the risk process working?                           |
| Does | Re-rates, closes, adds risks               | Checks owners know their risks and responses are ready |

**Remember:** stale entries call for a review; owners who did not know they owned a risk call for an audit.

### S-Curve vs Tornado Diagram

|         | S-curve (Monte Carlo)                                | Tornado diagram (sensitivity)              |
| ------- | ---------------------------------------------------- | ------------------------------------------ |
| Answers | How likely are we to hit the date or budget overall? | Which uncertainties drive the result most? |

**Remember:** the probability and impact matrix prioritizes individual risks; it is qualitative, not quantitative.

### Kaizen vs PDCA vs Six Sigma vs Value Stream Mapping

|                      | Core idea                                      |
| -------------------- | ---------------------------------------------- |
| Kaizen               | Continuous small steps from everyone           |
| PDCA                 | Pilot, check against the prediction, then act  |
| Six Sigma (DMAIC)    | Data-driven reduction of variation and defects |
| Value stream mapping | Separate value-adding time from waiting        |

**Remember:** if work spends most of its life queued between steps, map the value stream.

### Espoused vs Enacted Culture

|        | Espoused                                     | Enacted                                 |
| ------ | -------------------------------------------- | --------------------------------------- |
| Source | Mission statements, policies, survey answers | Observed behaviour and its consequences |
| Weight | Weaker evidence                              | Stronger evidence                       |

**Remember:** a "we learn from failure" poster means little if every incident review names someone to blame.

### ADKAR Knowledge vs Ability

|          | Knowledge                           | Ability                                     |
| -------- | ----------------------------------- | ------------------------------------------- |
| Means    | Knows how to change; can explain it | Can do it in practice under real conditions |
| Built by | Training, information               | Coaching, practice, time on the job         |

**Remember:** passed the theory test but still stalls in traffic is Knowledge without Ability.

### Proposed vs Enacted External Change

|            | Proposed                               | Enacted with a date              |
| ---------- | -------------------------------------- | -------------------------------- |
| Treated as | Risk                                   | Requirement or issue             |
| Action     | Analyze, plan a response, set triggers | Plan and deliver before the date |

**Remember:** do not baseline work for a rule that may never pass, and do not keep watching one that already has.

### External vs Internal Change

|               | External                                               | Internal                                       |
| ------------- | ------------------------------------------------------ | ---------------------------------------------- |
| Source        | Outside the organization                               | Inside the organization                        |
| Examples      | New law, competitor move, vendor retirement, sanctions | Reorganization, new sponsor, staff resignation |
| Handled under | External business environment                          | Organizational change, resources, governance   |

**Remember:** only external changes belong on the external-environment watch list.
